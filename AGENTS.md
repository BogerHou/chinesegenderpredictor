# Release and IndexNow rules

- Preserve the static Vercel architecture (`framework: null`, `dist`, `npm run build:verified`). Production uses `SITE_URL=https://chinesegenderpredictor.net`; previews remain noindex with no sitemap. Keep the default Vercel project alias removed and preserve Cloudflare/security settings.
- Follow `docs/DEVELOPMENT.md` and the user's browser-tab and temporary-file cleanup rules. For technical plans, image changes and releases, read `~/.codex/skills/vercel-cost-guard/SKILL.md` and its checklist. Use existing local static images; do not introduce runtime image transformations or Functions for IndexNow.
- Run the existing production tests/build/check and the preview noindex check before release. Verify the production response and published ownership file after deployment. Do not infer account quota from static source or claim zero cost.
- IndexNow is an explicit post-publication release step. Run `npm run indexnow -- --check`, inspect `npm run indexnow -- /changed-page/` (default dry-run, no network), then `npm run indexnow -- --submit /changed-page/` only for canonical URLs truly added or changed in this release. For deleted or moved URLs use `--submit --removed /old-page/`; `--file` accepts a line-separated list.
- Preserve `indexnow.config.json` and its `public/<key>.txt` static verification file; the build check verifies inclusion. Do not add build-time submission, visitor-triggered requests, daily full-sitemap submission, a new recurring task or an automatic retry loop. Keep the public verification key out of operational reports.
- Record HTTP 200 as received and 202 as received with key validation pending. Neither proves search-engine indexing or ranking effects. Keep technical implementation details out of visitor-facing pages.
