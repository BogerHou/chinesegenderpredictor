# 实施路线

基准日期：2026-10-08。工程方案已确定为静态站、esbuild + lunar、8 个首发路由，使用 Vercel 部署。下表是交付验收清单，不表示每项已通过验证；实际运行结果以项目构建和部署记录为准。

## 阶段一：上线前

| 工作 | 验收条件 |
| --- | --- |
| 农历与图表 | 校验春节前后、农历月末、闰月、图表年龄边界、非法日期和日期顺序；图表与计算结果来自同一数据；超范围不给编造结果 |
| 输入与结果 | 标签区分生日、受孕日与预产期；估算值有说明；结果展示农历年龄、月份和查表位置；重置与重复计算正常 |
| 内容与来源 | 方法、图表版本及闰月约定可查；准确性引用原始研究；传说不写成史实；无虚构医学审核 |
| 静态 SEO | 8 个路由均直接访问成功；独立 title／description、一个 H1、内部链接、404、robots.txt、sitemap；无占位域名进入正式版本 |
| 交互与可访问性 | 小屏可用、键盘可操作、输入错误明确、结果可被辅助技术读取；图表有文字含义，不只靠颜色 |
| 数据最小化 | 日期留在本地计算状态；不出现在 URL、埋点或公开日志；复制结果不自动创建可索引页面 |

日期校验依据：[香港天文台公历农历对照](https://www.hko.gov.hk/en/gts/time/conversion1_text.htm)及[2027 官方数据入口](https://data.gov.hk/en-data/dataset/hk-hko-rss-gregorian-lunar-calendar-conversion-table/resource/bc159cbb-e99c-435b-881e-74d4b03bd60a)。科学说明依据：[2010 年原始研究](https://pubmed.ncbi.nlm.nih.gov/20618730/)。证据核验日期均为 2026-10-08。

## 阶段二：Vercel 发布验收

1. 使用项目实际构建命令与静态产物目录配置 Vercel；不要另建 Sites 版本。
2. 预览环境限制索引；生产域名确定后，统一 canonical、sitemap、分享 URL 和域名跳转。
3. 在正式部署逐一验证 8 路由、资源路径、直达刷新、404、HTTPS、robots 与 sitemap；确认关键正文在 HTML 中可读取。
4. 用实际设备／浏览器核对表单、图表滚动、打印和结果复制；不得用未经验证的“通过”文字代替验收。
5. 交付正式链接和必要构建记录，清理本任务无用测试产物，保留可继续构建的源文件。

生产域名、Vercel 账号和部署权限取决于用户已有配置。若缺少账号登录，只报告具体阻塞，不宣称已上线。

## 阶段三：上线后 1–4 周

- 用户配置 Search Console 并验证所有权，提交正式 sitemap；检查索引和查询对应页面。
- GA4 是否启用由用户账号配置决定；只记录不含个人输入的使用事件，不传生日、受孕日、预产期或预测结果。
- AdSense 由用户在其账号申请与配置；不预期或承诺审批、收入。接入后复查布局跳动、性能和隐私说明。
- 先解决抓取、错误输入与移动端使用问题，再扩写文章。新站暂时没有足够流量时，不把零数据误判为零需求。

## 阶段四：第 2–3 月

执行[内容日历](CONTENT-CALENDAR.md)。重点完善结果差异解释和 2027 跨年案例；每次新增页面前确认是否能由现有页直接回答。检查核心查询是否被多个同义词页面分流，不批量建立结果参数页。

## 暂留用户账号配置的事项

GSC、GA4、AdSense 的账号登录、所有权验证、项目标识和最终开关不写入假值。开发与内容交付可以独立完成；接入后应重新核对真实网络请求与隐私文本。
